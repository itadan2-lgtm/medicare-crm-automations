Setup Guide

Seven steps, all in your web browser — a phone works fine. Runs on your own free accounts: no hosting, no subscriptions, no terminal.

⏱ ~20 minutes 💵 $0 to run ↻ do once
Before you start
What you'll need
A Notion account with your duplicated CRM template
A free GitHub account
A free Vercel account (only for the optional step 6)
This is a workflow aid, not legal advice. The SOA rule logic especially should get re-checked against current CMS guidance before you rely on it day to day.
New to this kind of setup? You don't need a coding background, and nothing here uses a terminal unless you choose to. Each step says exactly what to click and where, and the setup checks itself and tells you in plain English if something needs fixing. Nothing is permanent — the integration, the secrets, and the optional Vercel project can all be disconnected in a click if you back out.
Walkthrough
Seven steps
1
Duplicate the Notion template
If you haven't already, open the template and click Duplicate in the top right. Everything from here on refers to your copy — your IDs will be different from anything in this guide.
2
Create a Notion integration
Go to notion.so/my-integrations → New integration. Pick the same workspace your CRM is in (if you have more than one — this is the #1 thing people get wrong). Name it anything. Copy the secret it gives you — that's your NOTION_API_KEY.

Then connect it to your CRM, once: open your Home page in Notion, click the ••• menu (top right) → Connections → Add connections → pick your integration. (Notion used to label this "Connect to" — it's now "Connections." The list looks empty until you start typing your integration's name.) The databases inside the Home page come along with it.

Can't find your integration in the list? It's almost always because it was created in a different workspace than your CRM — the two must match. If step 5 later reports a database missing, open just that one and add the connection the same way.

3
Put the code on your own GitHub
First unzip medicare-crm-automations.zip on your computer. Then sign in at github.com (a free account is fine) and make a home for it:
  1. Click + (top-right) → New repository
  2. Name it anything (e.g. my-crm), keep it Private, click Create repository
  3. On the new repo's page, click uploading an existing file
  4. Drag in everything from the unzipped folder, then Commit changes
github.com/you/my-crm
Drag files here to add them to your repository Commit changes

Uploading the files is a one-time thing. GitHub keeps them safe, and the daily automation runs from here — free, on your own account.

4
Add your one secret
In your new repo: Settings → Secrets and variables → Actions → New repository secret. Name: NOTION_API_KEY. Value: the secret you copied in step 2. This is the only thing you ever have to paste into GitHub.
github.com/you/medicare-crm-automations/settings/secrets/actions
NOTION_API_KEYUpdated just now

Secrets are hidden from everyone once saved — including whoever wrote this code.

5
Run the one-time setup
Go to the Actions tab → One-time setup → Run workflow → click the green Run workflow button. That's the whole step — it finds your databases through the connection you made in step 2. Leave the branch dropdown and the optional link box alone.
github.com/you/medicare-crm-automations/actions
One-time setup
Optional — leave empty and setup finds your databases on its own…
Run workflow
When it finishes (about a minute), open the run — its Summary says in plain English whether all 7 databases connected, and if anything's off, exactly what to click before running it again (that's also the one case where it may ask you to paste your Home page link into the optional box). Once it's green, you're done: the checks run by themselves every morning from now on (8am ET), free on GitHub.
6
Add alerts & auto-import optional
Email or text alerts: add more secrets on the same screen as step 4 — SENDGRID_API_KEY, ALERT_EMAIL_TO, ALERT_EMAIL_FROM for email (SendGrid's free tier is plenty), or TWILIO_ACCOUNT_SID, TWILIO_AUTH_TOKEN, TWILIO_FROM_NUMBER, ALERT_SMS_TO for texts (Twilio charges a few cents per text). Skip this and results simply stay in each morning's run log.
Auto-import leads from a web form: deploy the included webhook to Vercel (free):

Add just NOTION_API_KEY and WEBHOOK_SECRET (any random string) under Vercel's Environment Variables. Point Tally, Typeform, or a plain form at https://your-project.vercel.app/api/lead-webhook.
7
Watch it work
Don't wait for tomorrow morning — trigger a run right now: Actions tab → Daily Compliance & Deadline Checks → Run workflow. Open the finished run to see what was checked and what was flagged (or watch your inbox, if you set up alerts).

Prefer running things on your own computer, or want to tinker? The same setup works locally — open a terminal in the project folder:
$ npm install
$ npm run setup
…a guided assistant asks a few questions and saves everything…
$ npm run doctor
Everything looks good.
Stuck on a step? Open your latest run in the Actions tab — its Summary explains, in plain English, what to fix. (On your own computer, npm run doctor does the same.) INSTRUCTIONS.md in the project covers the same ground in plain text.
